# 给 Gemini 的 CLI Team 前端任务书

这份文档可以直接交给 Gemini。视觉和布局由 Gemini 接续设计；现有规划可作为参考。代码已接入第一版功能骨架，下述原生运行 v2 提案仍未实现。

## 当前代码与分工（2026-10-12 更新）

Gemini 负责界面设计、布局和交互呈现。后端与数据一致性继续由 Codex 负责。请在现有工作副本继续修改，不覆盖整个目录。

- `ui/workbench/RoomWorkbench.tsx` 已接入聊天室、收件范围、成员接力、任务/成果/日志面板；`workbench.css` 是可以重做的基础样式，不是最终设计。
- `ui/App.tsx` 保存业务操作与异步保护，并将任务、日志、成果详情挂到工作台侧栏。可以调整呈现位置，保留这些回调的业务语义。
- `ui/workbench/ChatTimeline.tsx` 保留历史阅读位置，按房间恢复滚动，提供新消息提示。
- `ui/workbench/roomState.ts` 提供与后端一致的收件人合并和验收检查。正文 `@handle` 也会派工，停用成员不能被静默忽略。
- `ui/taskDrafts.ts` 和草稿 API 已支持 `{kind:"room-message",roomId}`。可保存 `body`、`recipientIds` JSON 字符串、`taskId`；不保存发送、执行或验收授权。草稿文字上限 24000 字，实际发送上限仍为 12000 字。
- 发送成功只清空原房间正文；切换房间后不得清空新房间输入。发送请求未结束时退出保存握手返回未完成。
- 验收备注为必填，最多 2000 字；pending/failed/stale 机器检查和未通过的独立评审均阻止接受。
- Antigravity 已修复内部增量正文聚合；SSE 仍只通知后重新读取，尚未向前端推送正文增量，不能做伪流式动画。

除了既有三项桌面场景，还新增 `npm run smoke:desktop -- --workbench-smoke`，覆盖延迟发送、失败草稿、房间隔离、重复消息、输入法事件、历史阅读位置及任务/日志侧栏。后续设计可以改变 DOM，但需同步维护行为回归。

## 文件边界

在已有 `ui/workbench/**` 上继续实现，必要时调整 `ui/App.tsx` 的入口及样式引用。

可以复用并逐步拆分现有 UI 组件；迁移 TaskCreateDialog、taskDrafts、TaskTeamFields、TaskInputPicker、TaskMaterials、TaskAssistance、TaskAssignment、TaskCoordination、ArtifactPreview、RunDiagnostics 时，保持业务语义。

- `server/**`、`desktop/**` 的运行和数据逻辑由后端/桌面实施负责，本批不改。
- `ui/api.ts`、`ui/types.ts` 是公共边界，先在 `ui/workbench/api/` 增加视图映射，避免修改旧合同影响其他界面。
- 依赖变更只在有具体必要时提出并说明影响；优先现有 React、TypeScript、lucide-react 与 CSS。
- 不修改 `.team` 用户数据、不清理历史、不覆盖其他成员工作。项目没有 Git 元数据时先记录拟修改文件，保持可恢复的本地修改范围。

## 当前后端不支持的部分

以下能力可以在明确标记的开发 fixture 页面预览，但生产页面不提供可点的假操作：

- 持久房间成员名单、单聊绑定、默认负责人、结构化 mention 路由。
- 真正的逐 token/工具结构化事件、事件游标回放、原生运行中提问与权限答复。
- 逐收件人送达状态、待发投递编辑/撤回、原生会话能力探测。
- 全量消息分页/搜索、全局待处理查询。
- 具体步骤级恢复预览、结构化文件批注和更多文件预览接口。

当前 API 失败必须显示真实失败，不能自动替换成 fixture。探测 v2 接口时，只有 404 才走旧接口；鉴权、网络或服务错误不能当成功降级。`/api/control/*` 不是普通前端接口。

第一阶段的实时更新仍是 SSE 通知后读取相关数据；运行正文没有事件时展示真实运行状态，不用定时器制造回复。

## 必须覆盖的画面与状态

| 画面 | 必须出现的真实状态 |
| --- | --- |
| 初次进入 | 无成员、未选择工作区/服务不可用、检测入口 |
| 聊天室 | 空消息、长消息、收件人预览、发送失败、旧数据范围提示 |
| 任务准备 | 保存中、材料部分失败、待重选、待办已创建、只允许首次启动 |
| 协作任务 | 规划、排队原因、进行中步骤、负责人咨询、人工问题、已暂停 |
| 执行记录 | 运行中、部分输出、失败原因、返回原任务 |
| 成果验收 | 文件检查失败、机器检查缺失/失效、评审要求修改、待用户接受 |
| 恢复 | 保留步骤数量、恢复原因、服务返回冲突后的刷新 |

演示数据必须包含上述异常场景，而不只有成功画面。生产中未记录的事实显示“未记录”或“尚不支持”，不推导为通过。

## 视觉与交互要求

按设计文档 token 实现浅色工作台。主阅读区为连续消息，右侧是当前任务检查区；使用紧凑的成员接力条表达实际协作。不要添加欢迎海报、大号统计卡或与任务无关的图表。

主操作始终可见；普通卡片不用重阴影。收件人、任务范围、错误原因用中文短句说明。代码和日志按需展开。状态变化不抢用户正在阅读的滚动位置。

## 建议工作顺序

1. 阅读现有组件与接口，记录复用点和文件范围。
2. 完成壳层、布局和各类状态的独立 fixture；fixture 入口不能成为生产默认。
3. 接入 legacy adapter，迁移房间和收件人，再迁移任务准备、协作面板、成果验收。
4. 保留旧入口便于对照，在独立测试数据范围跑完整流程；完成后再切换默认界面。
5. 对未实现的后端依赖列出具体接口和字段，不顺手扩展后端权限或伪造结果。

## 交付验收

- 运行 `npm test`、`npm run check`、`npm run build`，记录结果、失败和跳过项。
- 运行适合本次界面变更的桌面回归，覆盖任务准备、暂停/改派/继续、业务求助及日志/成果返回。
- 在 1040×700 和高缩放场景检查操作可见、长表单滚动、焦点、中文输入法 Enter 行为。
- 检查原有任务与成员数据仍可读；材料、草稿、幂等启动、验收门槛没有退化。
- 保存关键截图和回归收据到项目内 `work/`；交付说明包括修改文件、已接入能力、尚缺后端能力、实际验证结果。
- 固定执行器和 fixture 的通过不表述为真实模型协作已经通过。

研究阶段的旧基线为 241 项测试。接入修改后的验证见 `docs/validation/2026-10-12-workbench-integration.md`；任何既有结果都不替代 Gemini 修改后的重新验证。

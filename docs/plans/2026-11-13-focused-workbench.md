# 聚焦日常工作的界面优化

用户确认的问题：上一轮打通了配置往返，但默认页面仍同时展示暂停、失败、可审阅等提示，同一稿件又出现在历史、提示与成果列表中。目标是让用户打开项目后立即知道当前最需要做的一件事。

## 设计与范围

- 默认布局为左侧工作列表、右侧当前工作。项目标题、一个优先行动、对话、当前成果按顺序呈现；完整内容按需打开。
- 下一步由同一份状态规则决定。发布结果未知和正在提交优先处理；归档、暂停、缺少成员和失败继续如实表达。其他仍需处理的情况放在可展开的明确计数入口中，不误报为正常。
- 移除会话里重复的暂停条、待审条和失败列表；运行统计与全局暂停按钮不再常驻项目页顶部，设置入口继续可用。
- 左侧只承担工作切换与搜索。同一稿件默认只在当前成果处展示一次；历史成果放到成果下方展开，团队过程独立展开，搜索命中会自动打开相应记录。
- “交接、接续、调度”等内部用语留在详细记录；默认文案使用“暂停、继续、查看内容、等待检查、需要处理”。机器证据、成员说明和发布授权继续分别呈现。

保留轨道工作台的深蓝与冰青色：背景 `#080f1b`、内容 `#101e30`、文字 `#e2edf8`、辅助文字 `#8b9fb8`、操作色 `#65e5ee`、需处理色 `#ffbe73`。中文正文使用现有微软雅黑 UI；标题使用现有 Bahnschrift/中文回退；等宽字体只用于证据。减去重复边框和装饰，让一个行动与当前成果成为视觉重点。

```text
工作列表与搜索 │ 项目名                     项目选项
               │ 当前最需要做的事           [下一步]
               │ 其他待处理情况（按需展开）
               │ 对话                        资料 / 团队
               │ 你的要求与团队答复
               │ 当前成果：标题、配图、正文摘要
               │ 历史成果 / 团队过程（按需展开）
               │ 输入新的要求                         发送
```

## 分工

- 主代理：工作区布局、项目标题与行动区、左侧工作列表、全局顶部，集成、文档及交付。
- 状态代理：优先行动与其他情况的纯状态模型，相关有意义的状态回归。
- 会话代理：会话与单份当前成果、历史与团队过程折叠、定位与输入，独立会话样式。
- 验证代理：更新现有浏览器演练，新增默认信息量与隐藏记录可达性验证，生成实际截图。

## 验收

1. 暂停、失败、待审并存时，默认只出现一处推荐下一步，其他问题仍能从明确入口查到。
2. 默认只显示一份当前成果；历史稿件与工作阶段不挤占默认会话。搜索消息、工作和旧版稿件仍能定位。
3. 配置往返、草稿保存、结果未知冻结、独立审稿和桌面发布确认保持有效。
4. 用同一组真实服务演练数据在 1440 和 390 宽度复核截图；无横向溢出，覆盖内容不接受键盘焦点。
5. 运行 `npm test`、`npm run check`、`npm run build` 和浏览器演练；更新本地桌面包、快捷方式和 README 后正常提交推送。

不增加新后台服务，不迁移数据库，不修改官方 CLI 凭据或发布权限。

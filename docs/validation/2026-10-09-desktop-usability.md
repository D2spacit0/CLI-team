# 桌面体验第一批交付记录

日期：2026-10-09。对象：Windows Electron 桌面端。

这一批落实[使用体验研究](../research/2026-10-08-user-experience-review.md)中“能操作到底、输入不能丢”和“启动前准备团队、材料与完成标准”的改进。用户可以先准备任务、暂时离开再续写，并在准备完整后明确启动。10 月 8 日研究报告保留为改进前的观察记录；本文按本轮实现更新使用行为。

## 小窗口与任务内往返

弹窗正文获得独立滚动空间，标题和底部按钮保留在正文之外；表单内容较长时，滚动正文即可继续填写，不需要依靠放大窗口寻找按钮。键盘焦点提供可见轮廓。

从任务详情打开作业日志或成果预览后，可以返回原任务。任务、计划和成果版本仍一致且原输入框可用时，界面恢复原滚动位置，以及原输入框的光标或选中范围。计划或成果版本改变时，不把旧位置套到新内容上。位置恢复只针对同一窗口内的往返，重开应用的持久恢复范围是已经保存的草稿。

## 文字草稿与任务状态分开

新任务的目标、分工、完成标准、检查设置和材料清单，以及任务内的求助答复、返工意见、验收备注，保存到当前工作区。任务内草稿按任务和相关计划、问题或成果上下文区分。历史问题的答复草稿仅供查看和复制，不自动提交到新问题。

界面显示正在恢复、正在保存、保存成功或失败。保存失败时保留当前文字并提供重试；新建弹窗离开前等待保存，桌面退出或切换工作区前也会等待草稿保存。保存握手开始后暂时锁住输入和操作，取消离开后恢复编辑，避免“保存成功”之后的新输入被遗漏。应以界面的保存成功状态确认草稿已落到工作区。本地服务意外停止时保留当前窗口，方便复制尚未保存的文字。

恢复草稿不会创建执行、提交答复、发起返工或接受成果。验收备注可以恢复，接受缺失自动检查等授权勾选不持久化；回到验收界面仍需重新确认。新建中的“放弃草稿”只清除填写记录，已经创建的待办和材料副本会保留。

清除成功后从另一个入口新建任务，会使用该入口的执行方式和默认频道。已有持久草稿、未保存输入、保存或清除失败的内容不会被新的默认值覆盖。

## 启动前完成准备

新建协作任务和单人任务共用准备界面：填写目标，选择团队，描述完成标准，添加可选材料，最后选择“保存待办”或“准备完成并开始”。

- 团队选择显示已有技能描述。停用、缺失执行入口或不符合角色权限的成员有禁选原因；忙碌成员可以选择，并说明将排队。协作任务需要一名具备编辑权限的负责人和 1–4 名协作者，可另选独立评审者；负责人和评审者不列入协作者名单。管理成员后可返回继续填写，原人选失效时由用户明确更换。
- 完成标准可以使用自然语言。人工核对和运行自动检查分别呈现；自动检查填写程序及参数，每行一个参数，高级配置保留 JSON 数组。程序仍通过参数数组调用，不将模型提供的 shell 字符串当作检查命令。
- 输入材料仍限单份 8 MiB、每任务 64 份、合计 32 MiB。同名材料不能覆盖，首次启动后锁定，原文件不移动、不回写。

| 操作或异常 | 当前行为 |
| --- | --- |
| 保存待办 | 先创建未启动任务，再逐份导入并核对材料；不会启动成员 |
| 准备完成并开始 | 复用准备好的待办，全部所选材料核对成功后才请求启动 |
| 一份材料导入失败 | 保留原待办和已经导入的文件；显示失败项，允许重试或重新选择缺少的文件 |
| 单份材料重试 | 只处理对应材料，并保持任务未启动；完成全部准备后再选择保存或开始 |
| 创建成功但响应丢失 | 根据已保存的创建标识恢复原待办，幂等重试不会再创建一项任务 |
| 上传成功但响应丢失 | 重新读取材料记录并核对哈希，避免重复导入 |
| 原待办已经启动 | 新建准备入口的启动请求只接受从未启动的待办，不把重试当作再次执行 |

任务目标和分工在待办创建后固定，准备界面会说明正在续用该待办。草稿保存成功后可以关闭弹窗再继续；首次启动前仍可以增删材料。

## 文件恢复边界

材料草稿保存清单和必要的校验信息，不保存文件内容、`File` 对象或本机来源路径。同一窗口中关闭弹窗再打开，可以继续使用刚选择的文件；重开应用后，尚未导入的文件必须重新选择。

已导入材料先显示“已保存，待核对”，从原待办读取并核对材料记录及哈希后才视为本次准备完成。保存过清单不等于文件已经成功导入，选中文件也不等于任务已启动。

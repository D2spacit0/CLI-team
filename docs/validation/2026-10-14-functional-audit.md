# 2026-10-14 功能逻辑检查与 DSH 0.2 接入

本轮按现有功能检查正常流程、失败重试、状态恢复和操作入口，并修复已复现的问题。只更新源码和开发构建，未打包。测试使用项目内的独立目录，没有启动原工作区服务；根目录快捷方式仍指向 10 月 13 日的成品。

## 修复结果

| 问题 | 修改后的行为 |
| --- | --- |
| 消息已经送达，但响应丢失；重试重复发消息、派工和通知 | 发送前持久化请求编号。重试或刷新后先核对服务端回执；同一请求只产生一份消息、作业和通知。用户后来修改的文字继续保留 |
| 多收件人派工中途失败，只完成一部分 | 消息、派工、主控通知和回执在同一事务中提交；失败时整体回滚，回滚不发送状态事件 |
| 队列满时“创建并启动”失败，残留未知待办和频道 | 创建前核对队列容量，创建及启动使用事务，拒绝时不留下半成品 |
| 取消任务没有停止专属频道中的讨论会 | 暂停和取消共用任务运行范围，包含任务作业、关联咨询和专属频道讨论；其他共享频道任务保持独立 |
| 成果预览会检查版本，下载却可能读出变化后的文件 | 下载同样核对大小和 SHA-256，并直接发送已经核对的字节，避免再次读取不同内容 |
| “待我处理”从模型摘要、旧问题和旧反馈猜测操作 | 依据当前任务、计划及未答复问题分类。暂停和待返工不会被误列为等待答复，已完成的问题不会继续要求答复 |
| “去答复”跳到不存在的区域 | 直接定位到展开的任务协助区，显示当前问题和答复表单；桌面检查验证实际滚动位置 |
| 损坏的持久化路由编码使工作台恢复失败 | 对非法 URI 编码安全处理，继续恢复可用页面 |
| 主控审查、终审和讨论阶段缺少统一中文说明 | 任务进度、作业日志和聊天工作台复用阶段名称 |
| DSH 更新后仍引用旧 profile 中的 CLI | 发现并校验 Desktop 内置入口和版本；旧自动发现配置在成员空闲时迁移，保留模型选择、权限和会话 |
| DSH v4 日志结构变化导致外部会话缺失 | 支持 v3/v4 消息及模型事件，识别并排除子会话；不回退使用未知新版本的旧日志 |
| 模型请求失败只显示笼统错误 | 对网关 502/503/504 和请求超时提供对应的连接诊断提示 |

调度、执行和队列解释共用 `run-policy.mjs`，暂停与取消共用任务作业范围。移除了未被使用的 `workbenchAdapter.ts` 及其虚构的 v2 接口探测，减少重复状态和接口包装。

## DSH 实机验证的边界

本机安装为 `D:\Program Files\deepseek-harness\DeepSeek Harness.exe`，官方版本 **0.2.0-rc.2**。使用官方内置 CLI 和独立测试 profile，对本地固定 HTTP 模型端点完成两次请求，验证了 ACP、结构化回复、原生上下文恢复、v4 日志读取，以及 0.1.5-rc.1 会话迁移后恢复。真实模型调用为 **0**，固定端点调用为 **2**：[官方程序验证回执](../../work/functional-audit-20261014/installed-dsh.json)。

第一批有一次使用官方默认配置的真实请求失败。工作台没有指定模型覆盖，官方选择 `local/qwen38`；该次请求返回 **502**，当时的连接检查也超时。虽然 CLI 退出码为 0，这次业务结果仍失败：[历史失败回执](../../work/functional-audit-20261014/dsh-live.json)。这只说明当时那一次请求失败，不能据此断言模型服务当前不可用。

收到用户提供的官方客户端正常运行截图后，未修改官方模型、代理配置或凭据，重新使用相同工作区代理及官方默认配置验证：**首轮结构化回复、同一原生会话续接均通过**，随后 **真实单人文件任务、机器验收、用户接受、归档与恢复也通过**。见[本轮对话回执](../../work/ux-audit-20261014/dsh-live.json)、[文件任务回执](../../work/ux-audit-20261014/dsh-task.json)和[后续检查记录](2026-10-14-ux-audit.md)。当时 502 的具体原因没有查明，不再以“等待服务恢复”作为继续功能验证的前提。

未重新验证其他厂商的真实模型调用，也未执行成品打包验收。

## 使用本轮源码

在项目目录执行 `npm start` 可打开已构建的开发版桌面程序。若原工作区已有程序占用，请先正常关闭它。启动新版源码服务后，符合迁移条件且空闲的旧 DSH 成员入口才会更新；本轮独立测试没有替换正在使用的成品。

修改前的服务、界面、测试和项目清单位于 `work/functional-audit-20261014/before/`。所有失败回执与最终通过回执均保留，便于复查。

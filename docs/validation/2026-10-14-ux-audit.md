# 2026-10-14 日常操作与功能设计复查

承接[第一批功能检查](2026-10-14-functional-audit.md)，按用户要求继续检查实际操作，修改源码、重构重复逻辑并验证失败恢复。本轮未打包。测试和真实 DSH 文件任务均在项目内的独立目录运行，没有启动原工作区服务或修改原工作区任务。

## 用户能感受到的变化

| 发现的问题 | 改进后的行为 |
| --- | --- |
| 转交次数填 0 会变回 1，数值清空时也被强行补值 | 输入暂存为文字，校验后再转换；0 可以正常保存，超出范围不会提交 |
| 改一个设置却覆盖其他设置，甚至把调度暂停状态改回去 | 只提交编辑过的字段。运行参数保存和顶栏暂停各自只更新对应返回字段，迟到响应不覆盖其他设置 |
| 设置保存失败弹系统框，查看成员后团队选择消失 | 错误留在原表单，输入和选择保留；设置页内部导航不会丢内容，可明确放弃未应用的修改 |
| 连续点击频道或讨论提交会重复创建 | 界面提交锁加服务端持久化请求回执；重试、刷新和服务重启都复用原请求，事务失败整体回滚 |
| 讨论填到一半不能稍后继续，响应丢失后不知道是否已发起 | 频道和每个房间的讨论草稿独立保存；关闭或 Escape 先保存；未确认的请求冻结原参数，可“核对并重试” |
| 讨论人数超限或成员失效只能提交后报错 | 显示 2–4 人要求，满 4 人后不能再选；停用成员禁选，已失效选择可以移除，说明由谁汇总 |
| 成员配置失败后弹框，保存时还能改输入或关掉窗口 | 参数错误和服务错误在原表单显示；保存期间锁定输入与关闭操作，阻止重复保存；发现和启停也有进行中状态 |
| 日志首次加载失败会把面板关掉 | 保留日志面板和返回任务入口，可原地重试；迟到响应不改变已经返回的任务页面 |
| 点击复制没有反馈，拒绝剪贴板访问时没有说明 | 显示“已复制”或失败说明，可以重试或手动选择正文 |
| 下载失败可能把接口错误当成果保存，预览首次失败不能重试 | 先核对 HTTP 成功响应再下载；错误在当前入口显示，预览可原地重试；四个下载入口共用同一组件 |
| 同步外部会话时，较早读取的列表覆盖后读到的新答复 | 后完成的同步结果优先，保留最新答复和状态 |
| 代理留空说是直连，实际仍继承父进程代理 | 显式留空仅清理子进程代理变量；未指定代理时仍可继承，保留原有大小写 NO_PROXY 内容 |
| 一次网关失败被解释成模型服务当前不可用 | 诊断描述“本次请求”结果，提示检查所用配置及代理；历史失败与本轮成功分别保留 |

运行参数与频道/讨论表单分别抽成 `RuntimeSettingsForm`、`DiscussionDialog`，四个成果入口复用 `ArtifactDownload`。成员创建与更新合用提交数据，减少重复处理；沿用现有工作台视觉布局。

## 真实 DSH 验证

用户提供的截图显示官方客户端正常使用。重新检查时没有先改模型、官方配置或代理：工作区仍使用原代理，成员未指定模型覆盖，官方配置选择 `local/qwen38`。本轮证据为：

- [连接状态](../../work/ux-audit-20261014/connection-state.json)：直连及经过工作区代理均能收到端点响应；根路径 404 只证明可连接，不单独作为模型调用成功依据。
- [真实首轮与续接](../../work/ux-audit-20261014/dsh-live.json)：首轮返回包含随机验证文字的结构化 JSON；续接同一原生会话后准确保留该文字，两次均通过。
- [真实文件任务](../../work/ux-audit-20261014/dsh-task.json)：通过正常 TeamService/DSH 执行路径生成唯一的 `result.json`；独立 Node 验收核对目录、JSON 字段、数值 323 和中文数组。机器检查通过后停在待用户验收状态，随后测试用户接受、归档、恢复及文件字节保留，全部通过。

以上为两次对话调用及一项完整任务；文件任务内部含模型工具回合，此处不把工作台作业数当作底层模型 HTTP 请求数。默认模型证据为 `requestedModel: null`、`selectedModel: local/qwen38`。机器检查与文件字节断言是验收证据，成员自述单独记录。

第一批那次 502 仍保留为历史失败，当时原因未查明；它不能证明当前服务不可用。其他厂商真实模型及真实多厂商协作没有在本轮重新验证。
